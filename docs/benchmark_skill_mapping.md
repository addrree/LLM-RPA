# Benchmark Skill Mapping

MiniWoB validates reusable lower-level skills. It is not the full LLM planner/verifier pipeline. In MiniWoB reports `planner_used=false` and `verifier_used=false`; the benchmark checks controller, policy, grounding, extraction, and visual/spatial primitives that are reused by the main pipeline.

| Skill / capability | MiniWoB validation tasks | Result | Generic module/function | Main pipeline action/tool | Status in main pipeline | Notes |
| --- | --- | --- | --- | --- | --- | --- |
| semantic_click | click-button, click-dialog, click-link, click-menu, click-option, click-test | 18/18 basic/action subset | `app.interaction.action_grounder.ActionGrounder`, `app.executor.action_handlers.ActionHandlers` | `click_by_semantic_target` | available | Uses visible text/name/aria/title candidates and refuses wrapper-style generic clicks. |
| semantic_fill | enter-text, focus-text, login-user, find-word | 18/18 basic/action subset; 6/6 extraction subset | `ActionGrounder`, `ActionHandlers`, `app.extraction.extraction_controller` | `fill_by_semantic_target` | available | Textbox selection and fill remain controlled through executor/action handlers. |
| select/list/autocomplete | choose-list, use-autocomplete | 18/18 basic/action subset | `ActionGrounder`, `PageCandidateExtractor` | `select_by_semantic_target`, `choose_autocomplete_suggestion` | available | Selects real controls/options/suggestions from DOM/AX-like candidates. |
| numeric_extraction | find-greatest, odd-or-even | 6/6 extraction subset | `app.extraction.intent_parser`, `app.extraction.extraction_controller`, `ActionHandlers.extract_by_intent` | `extract_by_intent`, `find_max_numeric`, `evaluate_condition` | available | MiniWoB validates max-number and condition-driven action selection. |
| row/list/email_action | email-inbox, email-inbox-important | 6/6 extraction subset | `extraction_controller`, `ActionHandlers.find_row_by_condition`, `ActionHandlers.click_row_action` | `find_row_by_condition`, `click_row_action` | available | Main pipeline uses generic row condition/action primitives rather than email-specific selectors. |
| tree_navigation | navigate-tree | 6/6 extraction subset | `extraction_controller` tree-node matching, semantic click grounding | `find_tree_node`, `click_by_semantic_target` | available | Exact visible node matching is represented as semantic target selection. |
| visual_svg_recognition | count-shape, identify-shape, count-sides, grid-coordinate | 4/7 visual/spatial subset | `ActionHandlers.visual_observe`, `ActionHandlers.visual_extract_object_count` | `visual_observe`, `visual_extract_object_count`, `visual_click_by_geometry` | partial | SVG/DOM-exposed visual tasks are supported where geometry is reliable. |
| canvas_geometry | find-midpoint, circle-center, bisect-angle | controlled unsupported | visual/spatial controller boundary | `visual_click_by_geometry` | controlled unsupported / future work | Requires dedicated screenshot/canvas geometry reasoning; current behavior must fail as `visual_spatial_no_decision`. |
